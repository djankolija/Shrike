# v6.1: reasoning retention — when the settle branch should not exist

Amendment to [v6-dialect-normalized-cache.md](v6-dialect-normalized-cache.md).
Companion plan: [v6.1-implementation-plan.md](v6.1-implementation-plan.md).
Ruling by Davor, 2026-09-01, from the measured settle costs below.

## What was measured (2026-09-01, ornith15, --thinking off)

- Every completed turn takes the settle branch: the KV's live turn opens
  with the prefilled empty think block (`<think>\n\n</think>\n\n`, ids
  248068, 271, 248069, 271 — tokenizer-confirmed) which the settled
  history render strips. The divergence sits at the *start* of the
  answer region, so every later position shifts and the whole region is
  reconstructed.
- Steady state: restore the prior entry's snapshot + re-prefill the new
  turn (~1 s/request on the rig; seconds per card turn, background).
- The cliff: first settle on a server with no snapshot re-prefills the
  conversation whole (measured 44 s at ctx 1900), and a request arriving
  mid-settle joins it — the cost lands on user-visible latency.

## The ruling

The settle is a **compensation layer for a training-distribution
mismatch**: it exists for models trained NOT to see their prior
reasoning, where leaving generated thinking in KV violates what the
model expects (and where the pre-v6 re-render leaked thinking back *as
content*). When a model tolerates its own as-generated form — ornith
seeing its empty open/close block is exactly that — there is no mismatch
to compensate, and the branch should not be taken at all.

Default judgment (Davor, from usage across models, not only ours):
models normally *expect* to see their thinking-shape; gpt-oss is the odd
one out, and says so in its own model card ("CoT is dropped during all
previous turns").

## Design

One policy, two values, three facts:

- **`reasoning-retention: as-generated | stripped`** — server-level
  configuration, default `as-generated`.
- **`as-generated`**: history assistant turns render exactly as the
  model produced them. Thinking-off: inject the empty think block before
  content at every render site. Render ≡ KV, so v6's existing
  `settled == kv → unchanged` guard no-ops the entire settle branch —
  the settle machinery itself is untouched.
- **`stripped`**: today's behavior — canonical template render,
  compensation active.
- **Dialects may force `stripped`**: Harmony's text branch cannot render
  analysis in history at all; the config cannot override a structural
  requirement of the template.

All three render sites (request-time prompt, `settledBoundaryTokens`,
`settledLiveRegionTokens`) must apply the policy through the shared
renderer — changing only the settle side would move the reconstruction
cost from settle time to LCP-match time, not remove it.

## Scope and consequences

- **Uniform faithful render, both thinking modes.** Under
  `as-generated` the renderer renders each assistant history turn from
  what the message carries: echoed reasoning verbatim in its think
  block (the server already accepts `reasoning_content` on incoming
  assistant messages and maps it to `thinking:` —
  OpenAIModels.swift:591-600), the empty block when thinking is off,
  and nothing when a thinking-on client did not echo. **The client
  contract sets the cost, never the correctness**: a non-echoing
  client's render diverges from KV and degrades to the existing
  LCP-rewind path. Pi's compat knob (`requiresThinkingAsText`, already
  set for Gemma in ~/.pi/agent/models.json) is the echo mechanism;
  watch the per-request matched fraction for echo-fidelity drift.
- The v6 invariant is strengthened: every render — cold, hit, or miss —
  now produces byte-identical context including the block; nothing the
  model sees depends on a cache outcome.
- One-time prompt-cache invalidation at deploy (existing entries were
  settled block-less).
- Context cost: +4 tokens per historical turn under thinking-off.
